# NumX — أرقام عالمية

[![CI](https://github.com/Alaa91H/NumX/actions/workflows/ci.yml/badge.svg)](https://github.com/Alaa91H/NumX/actions/workflows/ci.yml)
[أحدث إصدار](https://github.com/Alaa91H/NumX/releases/latest)

تطبيق Android عربي (RTL) لتوليد أرقام الهاتف الخليوية والأرضية وفق خطط ترقيم الدول، وحفظها كجهات اتصال أو تصديرها إلى ملفات CSV/vCard، مع بحث دون اتصال، ودليل أرقام طوارئ مرجعي، وحذف آمن، واستعادة سجل الملكية، وإحصائيات دقيقة، ووضع داكن يتبع إعداد الجهاز.

الإصدار الحالي: **2.0.0** (`versionCode 3`).

## النطاق العالمي

- **252 دولة وإقليمًا**: 249 دولة في ISO 3166-1 إضافة إلى `XK` و`AC` و`TA`، مع الاسم العربي والعلم ورمز ISO ورمز الاتصال وحالة الدعم.
- **توليد الخليوي والأرضي**: لكل دولة خطة ترقيم مستقلة مبنية من بيانات libphonenumber المرجعية. «الاثنان» يعني الخليوي + الأرضي فقط، مع حذف الأرقام المشتركة بين الخطتين مرة واحدة.
- **8 دول/أقاليم بلا خطة خليوية** و7 مناطق بلا أي خطة قابلة للتوليد. تظهر هذه الدول في القائمة بحالة واضحة ولا يخترع التطبيق أرقامًا لها.
- **جزر وقواعد خاصة**: `TA` (تريستان دا كونا) أرضي فقط. `AQ`, `BV`, `GS`, `HM`, `PN`, `TF`, `UM` بلا بيانات ترقيم قابلة للتوليد.
- **استثناءات مقصودة**: لا يولّد التطبيق أرقام الطوارئ أو المجانية أو المدفوعة أو المشتركة أو VoIP أو الرموز القصيرة أو أرقام الخدمات. أرقام الطوارئ متاحة فقط كإدخال يدوي من تبويب الطوارئ.

## التسمية المحايدة ووسوم الملكية

اسم جهة الاتصال المولّدة عالميًا:

```
N-<أرقام E.164>
```

مثال: `+963 944 567 890` ← الاسم `N-963944567890`، والقيمة `+963944567890`.

لكل رقم مولّد ملاحظة تعريفية تحمل:

```
REF=N2;E=+963944567890;ISO=SY;T=MOBILE;P=1;G=<معرّف الدفعة>;C=<CRC32>
```

- `E` الرقم بصيغة E.164، و`ISO` الدولة، و`T` نوع الخط الفعلي (`MOBILE` أو `FIXED` أو `AMBIGUOUS`)، و`P` إصدار الخطة، و`G` الدفعة، و`C` تحقق CRC32.
- لا يحتوي الاسم أو الوسم على اسم تطبيق أو شركة أو مشغّل أو دولة بالكلمات.
- **التوافق مع N1**: تبقى جهات سوريا القديمة كما هي بالاسم `N-09XXXXXXXX` والوسم `REF=N1;N=09XXXXXXXX`. البادئات المدعومة: `091, 092, 093, 094, 095, 096, 098, 099`؛ وتُرفض `090` و`097`. الأرقام الجديدة تُنشأ دائمًا بوسم N2.
- **الطوارئ E1**: عند إضافة جهة طوارئ تُحفظ باسم وصفي مثل `شرطة سوريا — 112` ووسم `REF=E1;...`، ولا تُعدّ رقمًا مولّدًا.

## البحث دون اتصال

يعمل البحث بالكامل من بيانات مدمجة في APK، ولا يطلب التطبيق صلاحية الإنترنت:

- الدولة ورمز الاتصال، وصيغ E.164 والوطنية والدولية.
- نوع الخط: خليوي أو أرضي أو غير متميز (مثل الولايات المتحدة وكندا حيث تتطابق الخطتان).
- الصلاحية والتطابق مع خطة الترقيم، والطول المتوقع.
- المنطقة/المدينة عند توفر بيانات geocoder، مع طبقة أسماء عربية منسّقة وعرض الاسم الإنجليزي الأصلي عند غيابه.
- المشغّل الأصلي حسب بيانات carrier، والمناطق الزمنية، والمصادر.
- لا يعرض التطبيق اسم المشترك أو عنوانه أو حالة تفعيل الرقم، ولا يدّعي معرفة المشغّل الحالي بعد نقل الرقم (MNP). الخط الأرضي المجهول يظهر «غير متوفر» ولا يُنسب إلى مشغّل.

## أرقام الطوارئ والخدمات

- دليل مرجعي مدمج يضم **757 إدخالًا في 240 دولة/إقليمًا**، مصدره `ShortNumberMetadata` من libphonenumber 9.0.42.
- كل الإدخالات الحالية بمستوى تحقق `REFERENCE` وتظهر بوسم «مرجعي — غير مؤكد رسميًا» مع المصدر. لا يصف التطبيق أي رقم غير موثّق بأنه رسمي.
- الاختيار متعدد، ولا يوجد اتصال تلقائي أو حفظ تلقائي: لا تُحفظ جهة الطوارئ إلا بعد ضغط «إضافة المحدد».
- المناطق التي لا تتوفر لها بيانات تظهر بحالة صريحة، دون تخمين أو اختراع أرقام.

## التوليد والحفظ

### أوضاع الإخراج

- **جهات الاتصال**: إدخال دفعات صغيرة عبر `ContentProviderOperation` مع فحص مسبق لكل أرقام الهاتف الموجودة وتخطي المكرر — سواء أضافه التطبيق أو المستخدم.
- **ملف واحد عبر SAF**: يختار المستخدم الاسم والمجلد من منتقي Android الرسمي، وتُكتب البيانات مباشرة في الملف المختار دون نسخة مؤقتة.
- **تصدير مقسم إلى مجلد**: عند تجاوز مليون صف يُكتب النطاق على أجزاء `part-0001.csv` أو `part-0001.vcf` مع:
  - `manifest.json` يصف النطاق والدولة ونوع الخط والصيغة وعدد الأجزاء والصفوف.
  - `checksums.sha256` يحوي SHA-256 لكل جزء.
  - إمكانية مشاركة كل الملفات دفعة واحدة.
- **كل أرقام الدولة**: يعرض الإجمالي وعدد الأجزاء والحجم التقديري قبل البدء، ثم يصدّر النطاق الكامل إلى مجلد. لا يوجد سقف قديم بـ80 مليون رقم؛ النطاقات الكبيرة تُقسَّم تلقائيًا.
- **تصدير المضاف**: تصدير الأرقام المولّدة وجهات الطوارئ المضافة فقط، إلى ملف واحد أو مجلد مقسم.

### الصيغ

| الصيغة | الامتداد | الاستخدام |
|---|---|---|
| CSV | `.csv` | جداول وExcel وGoogle Sheets وأدوات الاستيراد |
| vCard 3.0 | `.vcf` | استيراد جهات الاتصال على Android وiPhone |

أعمدة CSV:

```
Name,Given Name,Family Name,Phone 1 - Type,Phone 1 - Value,
Country ISO,Calling Code,E.164,Line Type,Note
```

خرائط vCard: الخليوي `TYPE=CELL`، الأرضي `TYPE=VOICE`، غير المتميز `TYPE=VOICE` مع `X-ABLabel`، والطوارئ `TYPE=OTHER;X-ABLabel=طوارئ`.

### حدود عملية

| الوضع | الحد |
|---|---:|
| جهات الاتصال | 5,000,000 رقم في العملية الواحدة |
| الملف الواحد | 1,000,000 صف؛ ما زاد يتطلب تصديرًا مقسمًا |
| التصدير المقسم | بلا سقف عملي عدا مساحة التخزين |

أكبر خطة أرضية (ألمانيا) تقارب 7.824 تريليون رقم؛ لذلك لا يُنصح ببدء نطاق كامل إلا مع مساحة تخزين كافية ووقت طويل. يمكن الإلغاء في أي وقت، وتبقى الأجزاء المكتوبة محفوظة.

## الحذف والاستعادة

- يحذف التطبيق فقط جهات الاتصال التي أضافها، اعتمادًا على معرّفات `RawContacts` المخزنة في SQLite أو المستعادة من الوسوم.
- **استعادة السجل** تقرأ وسوم N1/N2/E1 من جهات الاتصال وتعيد بناء فهرس الملكية بعد إعادة التثبيت أو مسح بيانات التطبيق.
- الحذف الموحّد يشمل الأرقام المولّدة وجهات الطوارئ المضافة، ويعرض عدّادهما قبل التأكيد.
- تصفير الإحصائيات يمسح العدادات والجلسات فقط، ولا يحذف جهات الاتصال.
- رقم البداية يتقدم تلقائيًا إلى أول رقم صالح بعد آخر رقم محفوظ فعليًا، مع تخطي الفجوات بين الخطط.

## البيانات والخصوصية

- لا يطلب التطبيق صلاحية `INTERNET`؛ البحث والتوليد والطوارئ تعمل دون شبكة.
- لا يُرسل أي رقم إلى خادم، ولا يوجد تتبع أو إعلانات.
- البيانات المدمجة هي:
  - `PhoneNumberMetadata.xml` و`ShortNumberMetadata.xml` من libphonenumber 9.0.42 (Apache-2.0).
  - geocoder وcarrier المضمنان في مكتبات libphonenumber.
  - طبقات أسماء عربية منسّقة داخل `tools/metadata/overlays`.
- بصمات المصادر وكل ملف بيانات مسجلة في `manifest.json` و`sources.json`، ويعرضها التطبيق في تبويب الإحصائيات.

## البنية التقنية

- **Kotlin + Jetpack Compose**، واجهة عربية من اليمين إلى اليسار، ووضع داكن يتبع النظام.
- **NumberingPlan.kt**: خطط DFA محدودة الطول مع عدّ دقيق وتعداد مرتب ودمج BOTH عبر تقاطع DFA لتجنب التكرار.
- **MetadataRepository.kt**: تحميل بيانات الدول والخطط والطوارئ والمصادر من الأصول.
- **Lookup.kt**: بحث دون اتصال عبر libphonenumber geocoder/carrier والمناطق الزمنية، مع استثناء سوريا 091/092.
- **NumXDatabase.kt**: SQLite/WAL للجلسات والأرقام المضافة والطوارئ والمؤشرات والإحصاءات.
- **ExportManager.kt**: كتابة متدفقة عبر SAF، تقسيم إلى أجزاء، manifest، وSHA-256.
- **OperationController.kt + Foreground Service**: المهام الطويلة تعمل على مستوى التطبيق وتستمر عند ترك الواجهة أو إغلاق الشاشة، مع إشعار تقدم وإمكانية إلغاء.
- **ContactsManager.kt**: إدخال دفعات، منع التكرار، حذف آمن، واستعادة N1/N2/E1.

## البناء

المتطلبات: JDK 21 (المستخدم في CI)، Android SDK 37، وGradle Wrapper المرفق.

```bash
cd numx-android
./gradlew testDebugUnitTest
./gradlew lintDebug
./gradlew assembleDebug
```

معرّف التطبيق: `com.numx.app`.

## التحقق من بيانات الترقيم

```bash
python3 tools/metadata/build_metadata.py --check
python3 tools/metadata/validate_metadata.py
```

- `build_metadata.py` يبني الأصول بشكل حتمي من ملفات libphonenumber المثبتة بالبصمات، ويولّد DFA لكل خطة.
- `validate_metadata.py` يأخذ عينات عشوائية ثابتة من كل خطة ويسأل libphonenumber عن الصلاحية والنوع. النتيجة الحالية: **20,057 عينة، 0 فشل**، مع استثناء موثّق لبادئات سوريا `091/092` التي يدعمها التطبيق بينما يرفضها upstream.
- يتطلب التحقق وجود `libphonenumber.jar`؛ يمكن تحديد مساره عبر `LIBPHONENUMBER_JAR`.

## البناء الموقّع والإصدارات

يُبنى الإصدار الموقّع داخل GitHub Actions فقط. مفتاح التوقيع وكلماته لا تُحفظ في المستودع، بل تُحقن وقت البناء من أسرار المستودع.

### أسرار المستودع

| السر | المحتوى |
|---|---|
| `NUMX_KEYSTORE_BASE64` | ملف `numx-release.jks` مشفّرًا بـ Base64 |
| `NUMX_KEYSTORE_PASSWORD` | كلمة مرور مخزن المفاتيح |
| `NUMX_KEY_ALIAS` | اسم المفتاح داخل المخزن (`numx`) |
| `NUMX_KEY_PASSWORD` | كلمة مرور المفتاح |

### سير العمل

- عند كل دفعة إلى `main` أو طلب سحب: تحقق من بيانات الترقيم، اختبارات الوحدة، `lintDebug`، وبناء APK للتشخيص.
- عند دفع وسم يبدأ بـ `v`: بناء APK وAAB موقّعان، التحقق من بصمة الشهادة، ثم إنشاء GitHub Release ورفع الملفات و`SHA256SUMS.txt`.
- إصدار `2.0.0` يستخدم `versionCode 3` ويجب أن يبقى التوقيع متسقًا مع الإصدارات السابقة.

### إصدار نسخة جديدة

1. حدّث `versionCode` و`versionName` في `numx-android/app/build.gradle.kts`.
2. ادفع التغييرات إلى `main` وانتظر نجاح CI.
3. أنشئ الوسم وارفعه:

```bash
git tag -a v2.0.0 -m "NumX 2.0.0"
git push origin v2.0.0
```

4. راقب سير عمل الإصدار وتحقق من الملفات في صفحة **Releases**.

## الاستخدام

1. افتح تبويب **توليد** واختر الدولة من القائمة (252 دولة/إقليمًا). تظهر حالة الدعم والأطوال والإجمالي المتاح.
2. اختر نوع الخط: خليوي، أرضي، أو الاثنان.
3. اختر **جهات الاتصال** أو **ملف**، ثم الصيغة عند اختيار الملف.
4. أدخل رقم البداية (محلي أو NSN أو `+CC...` أو `00CC...`) وعدد الأرقام، أو اختر **كل أرقام الدولة**.
5. للملفات الكبيرة استخدم **تصدير مقسم إلى مجلد** للحصول على الأجزاء و`manifest.json` و`checksums.sha256`.
6. راجع نتائج البحث في تبويب **بحث**، وأضف أرقام الطوارئ من تبويب **طوارئ**.
7. من تبويب **إحصاء** استعِد السجل، صدّر المضاف، احذف ما أضافه التطبيق، أو صفّر العدادات.
8. يمكن ترك التطبيق أو إطفاء الشاشة أثناء العملية؛ تابع من الإشعار أو أعد فتح التطبيق.

## حدود واقعية

- حفظ ملايين جهات الاتصال يستغرق من عشرات الدقائق إلى ساعات حسب الجهاز ونسخة Android.
- فحص التكرار يقرأ أرقام الهاتف المحفوظة كلها قبل البدء، وقد يستغرق وقتًا مع ملايين الجهات.
- كتابة CSV لمليون صف تحتاج مساحة تقريبية ~180 MB، وvCard ~220 MB. استخدم التصدير المقسم للنطاقات الكبيرة.
- أرقام الطوارئ مرجعية ولم تُؤكد رسميًا من جهة وطنية في هذه النسخة؛ تحقق من الرقم المحلي قبل الاستخدام.
- الخطط مبنية من بيانات libphonenumber 9.0.42 وقد لا تعكس آخر تغييرات الترقيم.
